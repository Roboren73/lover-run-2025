## 二、本次体检发现并已修复（有测试佐证）

### 1. 🐞 真 Bug：残局会建议出非法牌（双端同病，已修）
`decompose()` 第8步把**王和百搭(红桃级牌)凑成"对子"**——但王+百搭不是合法牌型
（`classify` 返回 None，规则上百搭不能替王）。复现：手里只剩 `小王+红桃2`(打2)，
`lead_v2` 会建议出 `pair[小王 H2]` ——**照做就是出非法牌**。
Python 与 `webapp/guandan.js` 镜像同病。
**修复**：王不再参与百搭配对（只单出）；`lead_v2` 加了合法性安全网（建议前过一遍
classify，非法组合永不出口）。新增回归测试：双端各 5 例 + 随机27张×20组
"拆解覆盖全部牌且全部合法"模糊测试。

### 2. 计划质量：百搭补顺子（已实现）
原 decompose 的顺子只用自然牌，`34_67+百搭` 被拆成 4 手（对子+3单张）；
现在允许顺子借 1~2 张百搭（纯自然优先），同样的牌拆成 **1 手顺子**。

### 3. 计划质量：三带二合并（已实现）
原 decompose 从不组三带二，`999+44` 拆成 2 手；现在三同张自动带上最小对子
合成 **1 手 full_house**。

### 棋力测量（如实报告）
- V2(新) vs V1：100局×3种子 = 0.73/0.69/0.78（基线 0.74/0.70/0.63，均值 0.690→0.733）。
- **金标准**：从 git 取旧版 V2，新旧直接对打 400局×3种子 = 0.500/0.520/0.512，
  **均值 51.1%——略正但不显著**（1200局的标准差约±1.4pp）。
- 结论：Bug 修复是硬收益；两项计划优化对 bot 对打胜率提升有限，但
  **网页把 decompose 结果直接展示给人看**（"自动组牌"面板），拆解质量提升
  对真人用户的建议实用性是直接改善。不回退。
