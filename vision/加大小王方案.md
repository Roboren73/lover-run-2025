# 给认牌模型加"大王/小王"的方案（掼蛋必需）

## 结论先行（多智能体调研 + 核验后的硬结论）
**公开数据集里没有一个能区分大王(红)和小王(黑)——它们都只有单一个 `joker` 类。** 而掼蛋必须分大小王。
所以"找现成数据集直接用"行不通，**唯一可靠路径 = 自己拍大/小王标成两类，合并进现有 52 类数据，训成 54 类。**

## 调研到的数据集（按用途分档）
| 数据集 | 来源 | 图片量 | 类别 | 含王？ | 分大小王？ | 对掼蛋 |
|---|---|---|---|---|---|---|
| augmented-startups/playing-cards-ow27d（在用）| Roboflow | ~10100 | 52 | 否 | 否 | ✅ 当基础牌面数据最好 |
| Complete Playing Card Dataset | Kaggle/GitHub(Jayshah25) | ~2650 | 53 | 是(单类) | 否 | ⚠ 真实拍摄，可当补充，但 joker 要重标成两类 |
| 0lauk0/playing-cards-muou8 | Roboflow | ~1286 | ~53 | 是(单类 j) | 否 | ⚠ 同上 |
| mohammad-almasri / Kacem / cps-desk | Roboflow | 数百 | 53~54 | 是(单类) | 否 | ⚠ 量少；cps-desk 还是"分类"不是"检测"，不能直接用 |
| PD-Mera/Playing-Cards-Detection | GitHub | — | 52 | 否 | 否 | 代码可复用，数据无王 |

> roboflow/kaggle 页面在本环境被网络策略挡住，类数/图片量来自搜索摘要，标注了可靠度；GitHub 源可直接访问、较可靠。

## 推荐做法：自标大小王 + 合并训练（54 类）
仓库已备好脚本：`local_train/merge_jokers.py`、`train.py`、`export_onnx.py`。

### 步骤
1. **拍照**：用你实际打的那副牌，拍**大王(红)**和**小王(黑)**各 **30–60 张**。
   - 要多样：不同光线、角度、距离、和别的牌叠在一起只露左上角的样子也要拍几张（贴近真实牌桌）。
2. **标注**：上传到 Roboflow（或用 labelImg），给王画框、标两类：
   - 小王 → 类名叫 `joker_small`（或含 small/black/小/黑）
   - 大王 → 类名叫 `joker_big`（或含 big/red/大/红）
3. **导出**：选 **YOLOv8** 格式，下载这个小数据集（设为 `MyJokers`）。
4. **合并**（在本地 4090 环境里）：
   ```
   python local_train/merge_jokers.py --base 你的\Playing-Cards-4 --jokers 你的\MyJokers --out merged
   ```
   它会把 52 类 + 大小王 合成 **54 类**，王固定排在 **id 52(小王) / 53(大王)**。
5. **训练 + 导出**：
   ```
   python local_train/train.py --data merged\data.yaml --model yolov8s.pt --imgsz 960 --epochs 120
   python local_train/export_onnx.py --imgsz 960
   ```
6. **上线**：新 `best.onnx` 传到 `webapp/`；把 `merged/data.yaml` 的 names 发我，我把网页 `camera.html` 的 `CLASS_NAMES` 更新成 54 类（网页已支持识别 joker_small/joker_big → 小王/大王）。

## 提速备选
不想自己拍：可先用 Kaggle「Complete dataset」的 joker 图，但**仍要把它那一个 joker 类，按红/黑重新拆标成两类**——省不掉"区分大小王"这步。所以自己拍最直接、也最贴合你的牌。
